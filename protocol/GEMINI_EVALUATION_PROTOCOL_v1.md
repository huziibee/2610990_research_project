## Prediction isolation

Only instruction/utterance, scene, supplied dialogue and capability descriptions are model input. Record IDs may identify logs but supply no label information. Expected routes, strategy sequences, gold arguments, alternative reference interpretations and hypothetical replies remain in evaluator-only files. Reference answers are loaded only after immutable predictions are written; changing reference bytes must not change the initial model request. A negative leakage test must reject unexpected input keys. A simulated reply is released only after a matching clarification question, never preloaded into the initial context.

No protected case may influence model selection, prompt tuning, retry policy, thresholds or schema choices. Freeze prompt/schema/code hashes, ordered case IDs, dataset hashes and protocol before prediction. Score only after all primary initial predictions are locked; simulation requires its own locked reference coverage and matching rules. Log deviations and do not silently overwrite a failed run.

## Systems and budget fairness

S0 and S1 are the two main systems, as confirmed by the user: five runs each, **10 main runs total**. Both receive identical four-field inputs, common final schema and thinking enabled. S0 generates its complete task/clarification directly in one call capped at 8192 output-generation / 2048 thinking tokens. S1 uses **two actual sequential calls**, each capped at 4096 output-generation / 1024 thinking tokens: goal-first interpretation followed by joint grounding, evidence/dependency representation and unresolved-field checking. The second call sees the original public input and first-stage interpretation, never gold context. Their summed requested output/thinking caps match S0; repeated prompt/input tokens and actual consumption can still differ. Deterministic schema/capability/reference checks run for both; schema validity alone is never semantic success. The two call logs must establish that the external stages actually occurred.

Never compare thinking-enabled S1 exclusively to thinking-disabled S0. The primary budget comparison matches summed requested output/thinking caps, not inference-call counts or input-token cost. Measure all of these and actual reasoning/output tokens; equal maximum caps do not imply equal actual computation. Use the same two-stage limits on each clarification update for S1, and the same one-call limit for S0. No silent change of call architecture or retry budget after results.

Optional S2 uses a second interpretation that sees only original public input and its own prompt, not the first interpretation or its summary. Adjudication is triggered by exact structured dictionary inequality, not a semantic comparator; differing evidence lists or other structurally distinct yet equivalent outputs may therefore incur the extra call. It receives both interpretations plus input evidence and must cite that evidence; majority voting is not a correctness criterion. If retained, S2 comprises two independent complete two-stage S1 interpretations (four calls at 4096/1024 each), plus at most one adjudication call capped at 8192/2048 per turn. Its maximum summed generation/thinking caps are 24576/6144, three times the S0/S1 caps. Its results are a measured cost/accuracy trade-off; causal review-benefit claims require a separately frozen total-budget-matched S1 control. The user confirmed that S2 remains optional; activating it requires an explicit pre-experiment retention record. Do not promise 15 main runs or a six-point efficiency figure.

## Endpoints and scoring

Primary scientific endpoint is **complete-task semantic correctness after at most five simulated clarification turns**, including turn zero. A correct task has the intended goal, all required actions in a semantically valid order, correct typed required arguments and constraints, evidence-supported detail, and permitted capabilities. For a legitimately ambiguous case, a good question alone is **not a completed task**. It can receive initial policy-correctness credit, while complete-task success remains pending until a verified supplied reply leads to a correct final task. Report turn-zero complete-task correctness separately, including its legitimate-ambiguity limitation.

Primary status is **NOT_COMPUTED** until complete-task reference eligibility and simulated-answer coverage are independently verified and frozen before predictions. Route labels alone cannot activate it. Eligibility coverage must state numerator and denominator out of 100, the reasons for missing coverage, and whether all scheduled runs share it. The designated primary set remains all 100. Incomplete semantic-reference or simulated-answer coverage blocks the all-100 primary endpoint; do not quietly redefine it as a 99-case or smaller study. Any partial-coverage descriptive analysis must be labelled with its actual denominator and does not complete the primary evaluation. Do not change the primary endpoint to routing after seeing results. Retain a routing-only feasibility result when only routes are scoreable.

Initial policy correctness is secondary: execute requires a fully semantically correct task; clarify requires correctly recognizing an execution-critical unknown, asking a relevant answerable question covering at least one such unknown, not guessing unresolved values, and avoiding details already determined by context. Independently verified reference unknowns and question adjudication are required. Correct route alone is only route accuracy.

Semantic equivalence means equivalent goal/action meaning, referents, values, temporal relations, constraints and permissible ordering, not matching prose or JSON string equality. Deterministic schema and reference-link checks are separate. No synonym table or model self-review certifies semantics. A scoring rubric and fixtures with deliberately correct and wrong outputs must be validated. Borderline decisions are independently reviewed while blinded to system identity; disagreements and final resolution are retained. Missing independent adjudication yields NOT_COMPUTED rather than guessed credit.

Secondary metrics: execute/clarify 2x2 confusion matrix and accuracy over all authoritative routes; schema validity; required-field grounding accuracy (correct required field instances / verified required instances); unsupported details (unsupported committed argument/constraint instances / committed instances, plus cases with any unsupported detail / eligible cases); missing critical fields (missing/unresolved execution-critical instances on attempted execution / verified required instances, plus case rate); question necessity and critical-field coverage; unnecessary questions / asked questions and / all cases; failures to ask / legitimately clarify cases; turns to correct completion and unresolved-at-five rate. Always report denominators and undefined zero denominators explicitly. A capability-reference mismatch is a semantic failure, not merely an invalid JSON error.

Efficiency: input, final-output and reasoning tokens separately where provided, plus provider total tokens without inventing an arithmetic decomposition; call/attempt count; end-to-end latency P50/P95; optional streaming TTFT/throughput only if actually measured. Hosted GPU memory and local inference precision remain unavailable. Use three non-test warm-ups per configuration, excluded consistently; record retries and network delay. Primary latency is initial interpretation with retries and validation; simulated end-to-end completion latency is a separate series including all model turns and fixed local answer matching time. Report per scheduled case and per semantically correct resolved task. Cost uses dated provider price inputs and billed usage, never invented prices; zero correct tasks gives undefined cost per success.

## Clarification simulation

Freeze evaluator-only scenario records containing verified unresolved field IDs, allowed answer branches, question-to-field matching criteria, exact reply text and branch-specific complete task reference. Annotations that only describe a possible question are insufficient. Multiple hypothetical branches are evaluated separately under the same branch set for every system; aggregate equally within each case before across cases. Freeze branch weights before results. Report scenario coverage and cases, not just number of branches.

For each question, the evaluator matches only targeted critical fields to an eligible annotation. Supply only the relevant annotated reply, labelled `simulated`, as new dialogue. Do not supply the corrected complete task, route or hidden field map. Unnecessary, unanswerable, out-of-scope or unmatched questions receive no fabricated reply and terminate as unresolved with the reason. A reply may resolve linked arguments; revalidate all arguments without adding unannotated facts. Stop on verified correct execution, unresolved unanswerable question, model failure, or five questions. A model choosing execution incorrectly terminates as failure; the evaluator never tells it the error. Clearly distinguish these simulations from observed human conversations.

## Statistics, subgroups and failures

Use the same eligible cases, branches and five seed runs for each paired comparison. For each case and system, average binary correctness across its five runs (and prespecified equally weighted branches for simulation). Compute S1-S0 and, if retained, S2-S1 differences in percentage points. Bootstrap **cases with replacement**, retaining all paired systems/runs/branches for each sampled case, with 10,000 replicates and bootstrap seed 20261019. Use percentile 2.5/97.5 intervals. These estimate case-sampling uncertainty conditional on this corpus/run design; they are not population representativeness guarantees. Separately show five run values, mean, sample SD and range. Do not flatten case x seed rows into independent samples or treat deterministic replicas as new scientific trials. Primary S1-S0 endpoint is prespecified; S2, ablation and subgroup intervals are secondary/exploratory, with no uncorrected multiple-testing significance claims.

Freeze five removals independently: goal-first, structured grounding, scene context, dependency checking, dialogue history. Keep final schema, model, settings, validation and score rubric constant except for the explicitly removed mechanism. The no-structured-grounding condition removes intermediate evidence/argument reasoning, not final task fields needed by the common schema. The no-dependency condition removes cross-argument checks, not ordinary field validation. State any shared mechanism that prevents a clean removal. Use five runs for each, or preregister a reduced design before results; no post-hoc selective repetition.
